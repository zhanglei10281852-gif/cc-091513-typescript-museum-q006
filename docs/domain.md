# 领域说明

自然博物馆编辑部用本系统管理科学事实条目、文献引文、专家意见、译文和各渠道版面
（纸质展签、语音导览、线上图录、印刷图录）。

## 核心原则

1. **科学结论先形成带证据的候选更正**：分类学修订（学名、分布等）登记为事实上的
   *候选版本*，必须附更正依据；候选不覆盖任何在用文字。
2. **审核后才能进入指定发布日期**：候选版本必须通过**学科学审**（scientific）；
   标记为需要法定审核的版面还须通过 legal 审核；版面中的每种译文必须通过
   **语言审核**（language）。任一道未过，排期闸门拒绝并给出具体原因。
   驳回的候选不得发布——仍有争议的结论不会被提前发出。
3. **已出版版本保持可引用**：发布瞬间冻结快照（原文、各语言段落、引文清单）。
   新版本发布后，旧版面进入 `superseded`，但快照永不修改、永不删除。
4. **紧急勘误只能追加醒目标记**：对已发布版面只能 `append clarification`
   （【紧急勘误】/【来源撤回】/【编辑部说明】），原文纹丝不动。
5. **翻译绑定具体源版本**：译文记录 `sourceVersionId`，源版本绑定不可变；
   译文文字可修订，但每次修订使文本修订号（textRevision）递增，
   旧修订号上的语言审核自动失效，必须重新审核。
6. **来源撤回不自动认可替代结论**：引文撤回是独立事件，只追加 `CitationRetracted`；
   系统标出受影响段落（撤回标记中冻结 `affectedLanguages`）、在引文报告中标红、
   阻止引用该证据的新排期，但不会改写结论或自动采纳任何替代假说。
7. **过期草稿检测**：每条事实（及每条引文）是一个事件流，带单调递增 revision。
   命令必须通过 `If-Match: <revision>` 携带所基于的版本号；并发提交时后到者得到
   `412 stale_revision`，需刷新后重新合并。

## 事件溯源

系统唯一的事实来源是只增不改的事件日志（默认 `.runtime/events.jsonl`，JSONL）：

- 领域事件见 `src/domain/events.ts`（事实登记、候选提案、引文登记/关联/撤回、
  专家意见、审核提交、译文记录/修订、版面创建/改稿/排期/发布/取消、醒目标记追加）。
- 读模型由投影重放全部事件得到（`src/domain/projection.ts`）；重启即恢复。
- 任一文字都可经 `GET /trace` 追溯它经历的学术决定：提案依据 → 证据（含撤回状态）
  → 专家异议 → 学科/法定/语言审核 → 译文修订 → 版面排期/发布 → 追加标记。
- `GET /facts/:id/timeline` 返回原始事件流，可直接审阅。

## 枚举

`reference/domain.json` 保存公开枚举（内容状态、审核类型、发布渠道、事实类型、
审核决定、专家立场、标记类型）。启动时校验其与代码常量一致，漂移直接启动失败。

## 主要读模型

- `GET /facts/:id`：事实的全部候选版本（状态、审核轮次、引文有效性、异议计数、
  译文及语言审核状态）与各渠道版面（草稿/排期/发布/取代，含阻塞原因）。
- `GET /board`：按物种代码或展区过滤的馆方看板——各渠道**当前展示内容**（含醒目
  标记与已失效引文）、**待审核差异**（候选文字对照当前发布文字、计划发布时间、
  阻塞原因）。
- `GET /reports/citations`：引文有效性报告——撤回状态、撤回通知、被哪些候选/已发布
  版面使用（含该引文流当前 revision，撤回命令需用它做 If-Match）。
